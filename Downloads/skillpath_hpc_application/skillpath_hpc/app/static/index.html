PROJECT DOCUMENTATION

How SkillPath works

A working prototype for the Personalized Skill Development Recommendation System, HPC course CCSAI0302, Group 42.

SDG 4 · Quality Education

Problem statement

Students may find it difficult to choose technical and soft skills aligned with their interests, current knowledge, career goals and industry needs. SkillPath compares a learner profile with a small career-to-skill knowledge base and identifies gaps.

Objectives

  • Capture learner interests and existing skills.
  • Compare proficiency with system-defined career targets.
  • Rank skill gaps and explain recommendations.
  • Generate a prerequisite-aware learning roadmap.
  • Track progress and recalculate dashboard metrics from saved records.

Architecture

Profile form→FastAPI validation→Skill-gap engine→Roadmap→SQLite + dashboard

Recommendation method

Gap score 40%, skill importance 25%, interest match 15%, prerequisite readiness 10%, and time feasibility 10%. The resulting score is bounded to 0–100 and includes a written explanation. This is a deterministic rule-based recommender, not a trained machine-learning model.

HPC connection

The benchmark runs independent recommendation workloads sequentially and with a thread pool, checks output consistency, and records timing, throughput and environment details. It is a small local experiment, not a distributed or cluster-scale implementation. Threading can be slower for CPU-bound Python tasks.

Technology stack

Python, FastAPI, Pydantic, SQLite, HTML, CSS, JavaScript and Pytest. The frontend is intentionally served directly by FastAPI to keep local setup simple; React/TypeScript, Tailwind and Recharts are not used in this version.

Dataset, limitations and future scope

The initial knowledge base is manually curated and includes nine career paths. It is not an official industry dataset; target levels are illustrative system recommendations. Self-reported skill levels and the short optional quiz are not validated assessments. Authentication, multi-user authorization, mentor feedback, external course catalogue integration, and real cluster/distributed processing remain future work.

The uploaded Month 1 and Month 2 reports document problem understanding, research, feature planning and a proposed workflow; they do not document a completed prototype or measured test results. This application is the implemented prototype for the next integration and validation stage described in Report III.
